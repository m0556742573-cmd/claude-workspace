# 0001 — האתר על ה-VPS: nginx סטטי, ניתוב בקובץ Traefik כמו supabase.yml

**Status:** Accepted (2026-10-20)

## Context

יצחק ביקש אתר תדמית בסיסי בדומיין `y-h-m.com`, **על השרת שלו.** על אותו שרת רצים n8n, Easypanel ו-Supabase עם נתוני הלקוחות של גרינוואלד. ה-DNS מנוהל ב-Cloudflare, ו-`supabase.y-h-m.com` כבר עובד דרך Traefik בקובץ ניתוב סטטי (גרינוואלד, החלטה 0002).

## Decision

1. **קובץ HTML סטטי אחד** (`site/index.html`). בלי מערכת ניהול, בלי בסיס נתונים, ובלי טפסים.
2. מוגש מקונטיינר `nginx:1.27-alpine` בשם `site-y-h-m`, **בלי אף פורט פתוח**, על רשת `easypanel`, עם הקבצים ב-`/opt/site-y-h-m/html` בקריאה בלבד ו-64MB זיכרון.
3. הניתוב בקובץ `/etc/easypanel/traefik/config/site-y-h-m.yml`. **נקודת הכניסה ו-certResolver מועתקים בזמן ההרצה מ-`supabase.yml`**, במקום לנחש את השמות של Easypanel.
4. הכל דרך `scripts/deploy.sh`, שאפשר להריץ שוב ושוב, ויש לו מצב בדיקה (`--check`) שלא משנה כלום.

## מה נדחה ולמה

- **אפליקציה ב-Easypanel ממקור GitHub:** Easypanel היה מקבל גישה לכל הריפו, כולל מסמכי הפרויקטים של לקוחות. בלי GitHub, כל שינוי היה העלאה ידנית בממשק. **הדרך שנבחרה כבר מוכחת על אותו שרת.**
- **WordPress:** הרבה יותר ממה שאתר תדמית צריך, ומשטח תקיפה של PHP ותוספים **על שרת שמחזיק נתוני לקוחות.**
- **Cloudflare Pages:** פשוט יותר ולא נוגע בשרת בכלל. נדחה כי יצחק ביקש במפורש על השרת שלו. **אם זה ישתנה, זו החלופה הראשונה**: אותו `index.html` עובד שם כמו שהוא.

## Consequences

ניקוי מלא הוא שלוש פקודות ([`setup-guide.md`](../setup-guide.md)), ושום שירות אחר לא תלוי באתר. **אם Easypanel ישנה פעם את מבנה קבצי Traefik שלו, גם האתר וגם Supabase ייפלו יחד**, ותיקון אחד יחזיר את שניהם. אתר סטטי עם חיבור לקריאה בלבד לא מוסיף לשרת שום דבר שאפשר לתקוף מעבר ל-nginx עצמו.
