# מדריך הקמה — אתר ומייל ב-y-h-m.com

שלושה חלקים, לפי הסדר. **רק את חלק ב' אפשר להריץ שוב ושוב בלי לחשוב.** חלקים א' ו-ג' הם הגדרות חד-פעמיות ב-Cloudflare.

---

## חלק א' — רשומות DNS לאתר (Cloudflare, כ-5 דקות)

1. Cloudflare → `y-h-m.com` → **DNS → Records.**
2. **קודם להסתכל מה יש.** כשהדומיין עבר מ-Hostinger, Cloudflare ייבא את הרשומות שהיו שם. ייתכן שיש רשומת `A` או `AAAA` על `y-h-m.com` עצמו, או `CNAME` על `www`, שמפנות לדף חניה של Hostinger. **אם יש, צריך למחוק אותן או לערוך אותן. זו מחיקה, וההחלטה שלך.** את רשומת `supabase` לא לגעת.
3. להוסיף:

| Type | Name | Content | Proxy |
|---|---|---|---|
| `A` | `@` | **אותה כתובת IP שמופיעה ברשומת `supabase`** | 🟠 Proxied |
| `CNAME` | `www` | `y-h-m.com` | 🟠 Proxied |

4. **הגדרות SSL לא משנים.** מה שעובד היום ל-`supabase.y-h-m.com` יעבוד גם לאתר, כי הוא בנוי באותה דרך.

## חלק ב' — העלאת האתר לשרת (סקריפט, כ-2 דקות)

**מה הסקריפט עושה:** מעתיק את `site/` לשרת, מרים קונטיינר nginx קטן בלי אף פורט פתוח, וכותב קובץ ניתוב ל-Traefik ליד `supabase.yml`. **את ערכי הניתוב הוא מעתיק מ-`supabase.yml` שכבר עובד, במקום לנחש.** הוא לא נוגע ב-n8n, ב-Easypanel או ב-Supabase. פירוט ב-[`decisions/0001`](decisions/0001-site-on-vps-static-nginx-via-traefik-file.md).

**פעם ראשונה:** הסקריפט קורא את כתובת השרת מאותו קובץ שגרינוואלד כבר משתמש בו (`supabase-selfhost/scripts/.env.local`). אם הקובץ קיים אצלך, אין מה להגדיר. אם לא, צור את `scripts/.env.local` עם השורה `SITE_SSH_HOST=root@<IP של השרת>`. **הקובץ לא נכנס לגיט.**

מתוך התיקייה `myProjekts/אתר y-h-m/`, ב-Git Bash:

```bash
bash scripts/deploy.sh --check   # קודם: בדיקה בלבד, לא משנה כלום בשרת
bash scripts/deploy.sh           # ההעלאה עצמה
```

**הצלחה נראית כך:** שורות ירוקות, ובסוף `https://y-h-m.com/ -> HTTP 200`. **אם בפעם הראשונה מופיע 52x או אין תשובה:** לחכות דקה, כי התעודה עוד מונפקת, ולהריץ שוב `--check`. אם זה לא עובר, שלח לי את הפלט.

**עדכון תוכן:** עורכים את `site/index.html` ומריצים שוב `bash scripts/deploy.sh`. השינוי מופיע מיד.

**הסרה מלאה, אם תרצה פעם** (מחיקה, אז רק כשמחליטים):
`docker rm -f site-y-h-m` · `rm /etc/easypanel/traefik/config/site-y-h-m.yml` · `rm -rf /opt/site-y-h-m`

## חלק ג' — מייל אישי בדומיין (Cloudflare + Gmail, כ-20 דקות)

**זו המלצה, לא החלטה (W-002).** החלופות בסוף.

**הרעיון:** מייל שנשלח לכתובת שלך ב-`y-h-m.com` מגיע ל-Gmail הקיים שלך. אתה גם עונה מ-Gmail, והנמען רואה את הכתובת בדומיין. אין תיבה חדשה ואין אפליקציה חדשה.

### 1. קבלה — Cloudflare Email Routing (חינם)

1. Cloudflare → `y-h-m.com` → **Email → Email Routing → Get started.**
2. **Custom address:** הכתובת שתרצה, למשל `info` או השם שלך. **Destination:** ה-Gmail שלך. מאשרים את המייל ש-Cloudflare שולח ל-Gmail.
3. Cloudflare מציע להוסיף רשומות `MX` ו-`TXT` (SPF) → **Add records automatically.**
   ⚠️ **אם הוא מתלונן על רשומות MX קיימות** (שרידים מ-Hostinger), צריך למחוק אותן. **זו מחיקה, ההחלטה שלך.**
4. בדיקה: לשלוח מייל מטלפון אחר לכתובת החדשה, ולוודא שהגיע ל-Gmail.

### 2. שליחה — Gmail "Send mail as" דרך Brevo

Gmail צריך שרת SMTP כדי לשלוח בשם הדומיין. **Brevo נותן אחד בחינם** (מניח: עד 300 מיילים ביום בתוכנית החינמית. **צריך לבדוק** כשנרשמים).

1. נרשמים ל-Brevo → **Senders, Domains & Dedicated IPs → Domains → Add a domain** → `y-h-m.com`. Brevo מראה רשומות `TXT` ו-DKIM. **מוסיפים אותן ב-Cloudflare עם Proxy כבוי (DNS only)**, וחוזרים ל-Brevo ללחוץ Verify.
2. Brevo → **SMTP & API → SMTP** → יוצרים SMTP key. רושמים את השרת (`smtp-relay.brevo.com`, פורט `587`), את שם המשתמש שמופיע שם ואת המפתח.
3. Gmail → ⚙️ → **See all settings → Accounts → Send mail as → Add another email address.** הכתובת בדומיין, ואז פרטי ה-SMTP מסעיף 2 (TLS). Gmail שולח קוד אימות לכתובת החדשה, והקוד מגיע ל-Gmail דרך שלב 1.
4. אפשר לסמן את הכתובת החדשה כברירת מחדל, ו-"Reply from the same address the message was sent to".

### 3. ⚠️ SPF אחד בלבד, ו-DMARC

- **מותרת רשומת SPF אחת לדומיין.** אחרי שני השלבים צריכה להיות **שורה אחת** שמכילה את שניהם:
  `v=spf1 include:_spf.mx.cloudflare.net include:spf.brevo.com ~all`
  **שתי שורות `v=spf1` נפרדות שוברות את שתיהן**, וזו הטעות הנפוצה ביותר כאן.
- להוסיף DMARC במצב ניטור בלבד: `TXT` בשם `_dmarc`, תוכן `v=DMARC1; p=none`. **מקשיחים אחרי שבועיים שבהם הכל מגיע.**
- **בדיקה:** לשלוח מ-Gmail בשם הכתובת החדשה ל-mail-tester.com. ציון 9 ומעלה = תקין.

### 4. מה זה אומר לאקספו לידים

שם מתוכנן שהמערכת תשלח מיילים מ-`y-h-m.com`. **המלצה (W-004):** שהמערכת תשלח מתת-דומיין נפרד, למשל `mail.y-h-m.com`, ולא מהדומיין הראשי. **הסיבה:** מייל המוני שמישהו מסמן כספאם פוגע במוניטין של הדומיין ששולח אותו. בתת-דומיין, המייל האישי שלך לא נפגע. ובנוסף לתת-דומיין יש SPF משלו, ואין צורך לגעת בשורה שלמעלה.

| חלופה | למה לא עכשיו |

| **שרת מייל על ה-VPS** | ספקי VPS נוטים לחסום את פורט 25, מיילים משרת חדש נופלים לספאם, ותחזוקה מתמדת. **ועל השרת יושבים נתוני הלקוחות של גרינוואלד.** |

| **Google Workspace** | הכי נקי, אבל בתשלום חודשי לכל משתמש. **הדרך הנכונה כשיהיו עובדים**, ולא בשביל כתובת אחת |
