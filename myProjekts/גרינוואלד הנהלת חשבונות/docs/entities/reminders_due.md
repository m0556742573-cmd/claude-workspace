# reminders_due — מה לשלוח היום (VIEW)

> **חריגה מודעת מהכלל "קובץ לכל טבלה"** — זהו VIEW.

## מה זה ולמה זה משרת

**זו הסיבה שישות 34 קיימת בכלל.**

[`reminders`](reminders.md) מחזיקה שורה לכל חובה. הוויו הזה **מקפל אותן לשורה אחת לכל לקוח לכל יום** — כלומר **הודעה אחת** שמפרטת את הכל, במקום ארבע הודעות בבוקר אחד.

המקור: *"תזכורות היו מפוזרות בשלושה מקומות ומייצרות סיכון שהלקוח יקבל שלוש הודעות נפרדות באותו יום."*

## המספר שמצדיק את הישות

```
77 תזכורות בודדות  →  38 הודעות
```

**רוזנברג, 08/02/2026:** הודעה אחת עם **ארבע** חובות — מקדמות, הגשת מע"מ, תשלום מע"מ, הגשת פנסיה — במקום ארבע הודעות.

## מה בשורה

| | |
|---|---|
| `client_id` / `client_name` / `scheduled_for` | למי ומתי |

## ⚠️ חובה שהושלמה נושרת — בלי טריגר

הוויו מסנן על סטטוס החובה (`not is_closed`). **אין טריגר שמבטל תזכורות**, ולכן אין מה לסנכרן — **וחובה שנפתחת מחדש מקבלת את התזכורת שלה בחזרה בחינם.**

## ⚠️ שליחה אינה בנויה

תבניות הודעה (ישות 32) ואינטגרציית הערוצים אינן קיימות. יש `sent_at` בלבד, **ואין מזהה מנה ואין רשומת מסירה** — להמציא אותם עכשיו היה ניחוש של צורה שאין לה צרכן.

`security_invoker = true`. **רשימת העמודות מוקפאת ביצירה** — ר' [`decisions/0005`](../decisions/0005-rls-enabled-no-policies-yet.md).
