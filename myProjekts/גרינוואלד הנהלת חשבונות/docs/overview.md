# סקירה — CRM/ERP למשרד גרינוואלד הנהלת חשבונות

## למה הפרויקט קיים

מערכת CRM/ERP למשרד המשלב הנהלת חשבונות, חשבות שכר וייעוץ מס — כ-90 לקוחות, כ-6 עובדים.

עשר מטרות-על מניעות את התכנון, ובראשן: אפס פספוס מועדים רגולטוריים, סוף לרדיפה אחרי חומר מהלקוחות, אפס הקלדה כפולה, תמונת לקוח אחת, שקיפות צוות, רווחיות פר-לקוח, גבייה ותזרים, פרואקטיביות בזיהוי הזדמנויות וסיכונים, תיעוד מגן משפטי, וקליטה מסודרת. (פירוט מלא במקור: `סיכום_איפיון_מלא_המערכת.md`, בתיקיית Downloads בזמן הכתיבה — כדאי להעביר עותק לתוך הפרויקט בהמשך.)

## הקשר רחב יותר

הפרויקט הזה הוא גם הבסיס למיצוב המקצועי של יצחק כ**ארכיטקט מערכות עסקיות** — מי שמתרגם מורכבות עסקית למבנה בר-בנייה, נבדל מ"בונה no-code". שש תקרות שנצפו בפועל בעבודה עם Origami (מודל נתונים, ביצועים, הרשאות, לוגיקה, אינטגרציה, ממשק) הובילו להחלטה לבסס עבודה עתידית — גם בפרויקט הזה וגם כמודל עסקי — על שכבת Postgres/Supabase.

## מודל הנתונים

33 ישויות (אחרי איחודים), מחולקות לקבוצות: ליבה (לקוח/איש קשר/עובד משרד/סוג ישות), שירותים וחובות, חומר ומסמכים, שכר, פעילות CRM, כספים, קליטה ותפעול, ייחוס ותשתית. פירוט מלא בהמשך ב-`architecture.md` וב-`סיכום_איפיון_מלא_המערכת.md`.
